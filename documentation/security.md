# Security and operational boundaries

- **Network:** private interface binding must be explicitly configured; only HTTPS 8443 is published. No public exposure or port forwarding. Review the NAS firewall and VPN separately. The Compose network is internal. Neither raw ICM nor a Graphify administration endpoint is published.
- **Identity:** a unique random bearer token for each client, SHA-256 hashes in the mounted credential file, constant-time digest comparison, explicit project allowlist, explicit write permission. Credentials load at startup; restart for rotation/revocation. Store raw token files outside Git. Local NAS administrators can read live knowledge and credentials; this is not a tenant boundary against a hostile host admin.
- **Filesystem:** gateway has no source-repository mount. Graphs/config are read-only. Vault access is confined to `Projects/<slug>` with traversal and symlink checks. Agent writes use slug names, atomic replacement, and hashes; human-owned notes cannot be updated through these tools. Restrict SMB users so they cannot introduce symlinks or race filesystem replacements; a hostile writer with direct access to the same directories is outside the gateway's protection boundary.
- **Processes:** non-root UID/GID, dropped capabilities, no-new-privileges, read-only image, bounded temporary memory, process/memory/CPU limits, no socket mounts. One gateway worker and one replica only. Synchronize clones on a trusted host with Git hooks disabled by the script. No repository-supplied commands are executed by indexing.
- **Requests:** 64 KiB real-body cap, ten-second body idle timeout, 60 requests/minute per client, 16 requests in flight, 30-second ICM command timeout, query/result/traversal caps. The fixed token budget is conservatively applied as bytes; it is not an exact tokenizer. Authentication errors, rate limits, method/path/status/latency are logged without tokens, note bodies, or memory contents. Upstream libraries may log exception summaries; protect logs as context data.
- **Confidentiality:** code-only indexing skips semantic/media providers. Filenames and source snippets can still contain secrets. Review repositories before ingestion. A private GitHub repository is not a place for live databases, credentials, vault content, or TLS keys.
- **Backups:** archives are owner-only on POSIX but Windows/SMB ACLs must be checked separately. Keep encrypted off-device copies. Close human vault editors for consistent file snapshots. SQLite backups use the backup API, never live file copying. Restore rejects traversal, links, special files, oversized archives, checksum mismatches, and nonempty targets. SHA-256 detects accidental corruption; it does not authenticate an archive against an attacker who can replace it and its manifest.
- **Supply chain:** base images use manifest digests; ICM source uses a fixed commit and Cargo.lock; Python wheels use a hash-locked dependency export. Python graphifyy 0.9.91 was checked against official package metadata/source. These pins support repeatable dependency selection; they are not a completed vulnerability audit or a claim of bit-for-bit Docker reproducibility. Debian toolchains and transitive build behavior still matter. Upgrade deliberately and revalidate.

The CA is internal and must be trusted explicitly by clients. Do not expose its private key, disable client TLS verification, or use plaintext bearer credentials over untrusted networks. If an existing trusted private reverse proxy is preferred, adapt TLS routing only after reviewing that proxy; the initial repository does not modify any existing NAS service.
